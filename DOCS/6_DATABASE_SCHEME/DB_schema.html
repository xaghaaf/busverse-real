Overview

Introduction

The BusVerse schema is organized into 15 logical domains across 106 tables. v2.1 completes the model promised by the Features doc, adds support infrastructure, RBAC, user preferences, business operations, provider logs, CCTV, and booking modification history. Every status column uses a native enum. Every soft-delete table has partial indexes. Every foreign key has a documented cascade policy.

Why PostgreSQL: ACID transactions for money, native JSONB, pg_trgm for fuzzy search, PostGIS for geography, and mature tooling. All required. No alternative comes close for a real booking platform.

Conventions

Every table follows these rules.

Naming & Types
RuleValue
Tablessnake_case, plural
Columnssnake_case, singular
Primary keysid UUID DEFAULT gen_random_uuid()
Foreign keys<singular>_id — always with ON DELETE clause
Timestampscreated_at, updated_at — UTC
Soft deletedeleted_at where needed; partial indexes on active rows
MoneyINTEGER in paise. No floats.

Sample Queries

Most common patterns for the backend.

Search buses on a route for a given date

SELECT s.id, s.departure_at, s.arrival_at, s.base_fare,
       b.registration_number, bm.name AS bus_model,
       o.company_name, o.quality_score,
       (bm.capacity - COUNT(bp.id)) AS seats_available
FROM schedules s
JOIN buses b ON b.id = s.bus_id
JOIN bus_models bm ON bm.id = b.bus_model_id
JOIN operators o ON o.id = s.operator_id
LEFT JOIN booking_passengers bp
  ON bp.schedule_id = s.id AND bp.cancelled_at IS NULL
WHERE s.route_id = $1
  AND s.departure_at BETWEEN $2 AND $3
  AND s.status = 'scheduled'
  AND s.is_test = false
GROUP BY s.id, b.id, bm.id, o.id
ORDER BY s.departure_at ASC;

Atomic seat lock

INSERT INTO seat_locks (schedule_id, seat_number, user_id, session_id, expires_at)
VALUES ($1, $2, $3, $4, now() + interval '5 minutes')
ON CONFLICT (schedule_id, seat_number) DO NOTHING
RETURNING id;
-- 0 rows = seat already locked

Convert lock to booking (atomic transaction)

BEGIN;

DELETE FROM seat_locks
WHERE schedule_id = $1 AND seat_number = $2 AND session_id = $3;

WITH new_booking AS (
  INSERT INTO bookings (
    booking_ref, user_id, schedule_id, status, payment_status,
    booking_type, total_fare, convenience_fee, total_amount,
    boarding_stand_id, dropping_stand_id
  )
  VALUES ($4, $5, $1, 'confirmed', 'captured',
          'regular', $6, $7, $8, $9, $10)
  RETURNING id
)
INSERT INTO booking_passengers (
  booking_id, schedule_id, seat_number,
  passenger_name, passenger_gender, fare_paid
)
SELECT id, $1, $2, $11, $12, $6 FROM new_booking;

COMMIT;

Latest GPS for a trip

SELECT location, speed_kmph, heading, recorded_at
FROM driver_locations
WHERE schedule_id = $1
ORDER BY recorded_at DESC
LIMIT 1;

Operator settlement report

SELECT COUNT(b.id) AS total_bookings,
       SUM(b.total_fare) AS gross_fare,
       SUM(COALESCE(r.amount, 0)) AS total_refunds,
       SUM(b.total_fare) - SUM(COALESCE(r.amount, 0)) AS net_payout
FROM bookings b
LEFT JOIN refunds r ON r.booking_id = b.id AND r.status = 'processed'
JOIN schedules s ON s.id = b.schedule_id
WHERE s.operator_id = $1
  AND b.created_at BETWEEN $2 AND $3
  AND b.status IN ('confirmed', 'completed')
  AND s.is_test = false;

Check if user is blacklisted

SELECT 1 FROM blacklisted_entities
WHERE (entity_type = 'phone' AND entity_value = $1)
   OR (entity_type = 'email' AND entity_value = $2)
   OR (entity_type = 'ip' AND entity_value = $3)
   OR (entity_type = 'device_id' AND entity_value = $4)
  AND (expires_at IS NULL OR expires_at > now())
LIMIT 1;

Support ticket SLA dashboard

SELECT
  status,
  COUNT(*) FILTER (WHERE sla_due_at < now()) AS overdue,
  COUNT(*) FILTER (WHERE sla_due_at BETWEEN now() AND now() + interval '1 hour') AS due_soon,
  COUNT(*) AS total
FROM support_tickets
WHERE status IN ('open', 'in_progress')
GROUP BY status;

Migration Strategy

How schema changes happen safely in production.

Tool: Prisma Migrate or Drizzle Kit. Versioned SQL, checked into Git, applied in order.

Rules for Every Migration
  • Backward-compatible first. Add columns nullable. Backfill. Then NOT NULL.
  • Never rename columns. Add new, migrate data, drop old.
  • Never drop columns directly. Mark deprecated, drop after 30 days.
  • CREATE INDEX CONCURRENTLY on large tables.
  • Test on staging first. Restore prod backup to staging, run migration, verify.
  • Every migration reversible. Or documented why not.
  • Money tables never modified in place. Add columns only.

Enum migration strategy

-- Adding a value to an enum (safe, no lock)
ALTER TYPE booking_status ADD VALUE 'refunded' AFTER 'cancelled';

-- Never remove enum values — mark them deprecated in code instead
-- Never rename enum values — add new, migrate data, remove old

Solo migration workflow

  1. Write migration locally.
  2. Apply to local DB. Run tests.
  3. Commit migration file to Git.
  4. Deploy to staging. Smoke test.
  5. Restore recent prod backup to scratch DB. Run migration. Verify queries.
  6. Apply to production during low-traffic window.
  7. Monitor error rates 30 min post-migration.
  8. If issues: rollback with reversal migration.
