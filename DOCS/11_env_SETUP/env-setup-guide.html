Section 01 // Toolchain

Windows 10 Native Toolchain Installation

Run this single PowerShell block with Administrator privileges to install the core runtimes, compilers, and native service managers[cite: 15].

Run in Administrator PowerShell
Installs Node 22, Git, Python, C++ Build Tools, and Native Redis[cite: 15]
# 1. Enable Windows Developer Long Paths (prevents node_modules path limit errors)
Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name 'LongPathsEnabled' -Value 1

# 2. Install Core Runtimes & Version Control via Winget
winget install OpenJS.NodeJS.LTS --version 22.14.0 --accept-source-agreements --accept-package-agreements
winget install Git.Git --accept-source-agreements --accept-package-agreements
winget install Python.Python.3.12 --accept-source-agreements --accept-package-agreements

# 3. Install Visual Studio C++ Build Tools (Required for argon2 and native node-gyp builds)
winget install Microsoft.VisualStudio.2022.BuildTools --override "--passive --config C:\vs_config.json --add Microsoft.VisualStudio.Workload.VCTools"

# 4. Install Memurai (Native Redis 7-compatible engine for Windows)
winget install Memurai.MemuraiDeveloper --accept-source-agreements --accept-package-agreements

# 5. Enable Corepack and activate pnpm v9
corepack enable
corepack prepare pnpm@9.15.4 --activate

Section 03 // Persistence Layer

PostgreSQL 16 & PostGIS Installation

On Windows, PostGIS must be installed alongside the EnterpriseDB PostgreSQL installation to avoid missing extension errors[cite: 10, 15].

1. Install PostgreSQL 16 & PostGIS Bundle
# Install PostgreSQL 16 using winget
winget install EnterpriseDB.PostgreSQL.16 --accept-source-agreements --accept-package-agreements

# NOTE FOR WINDOWS 10:
# PostGIS is an add-on on Windows. Open "Application Stack Builder" from your Start Menu:
# 1. Select "PostgreSQL 16 on port 5432"
# 2. Expand "Spatial Extensions" -> Check "PostGIS 3.4 Bundle"
# 3. Complete the installation wizard using default parameters.
2. Database Initialization Script
Execute in PowerShell to provision user, database, and extensions[cite: 10, 15]
$PG_BIN = "C:\Program Files\PostgreSQL\16\bin"
$INIT_SQL = @"
DO `$do`
BEGIN
   IF NOT EXISTS (SELECT FROM pg_catalog.pg_roles WHERE rolname = 'busverse') THEN
      CREATE ROLE busverse WITH LOGIN PASSWORD 'busverse_dev_password' SUPERUSER;
   END IF;
END
`$do`;
CREATE DATABASE busverse_real OWNER busverse;
\c busverse_real
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
"@

$INIT_SQL | & "$PG_BIN\psql.exe" -U postgres -h localhost -p 5432
Section 04 // Cache & Locks

Native Redis Engine (Memurai)

Memurai provides an in-memory storage engine natively built for Windows, handling distributed locks (SET NX) and Redis Streams without Docker or WSL[cite: 5, 10, 15].

Verify & Configure Service
# Check if Memurai service is running
Get-Service -Name "memurai" | Select-Object Name, Status, StartType

# If not started, start the service:
Start-Service -Name "memurai"

# Verify connection via native CLI
& "C:\Program Files\Memurai\memurai-cli.exe" ping
# Output must be: PONG

Automated .env Engine

Executes zero-touch cryptographic key generation and distributes verified environment variables to the 7 required application and service paths[cite: 10, 14, 15].

Execute in Repository Root (D:\BUS_VERSE\BUS_VERSE_REAL)[cite: 15]

# ------------------------------------------------------------------------------
$RepoRoot = Get-Location

# 1. Generate High-Entropy Cryptographic Keys (256-bit Hex)
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$bytesAccess = New-Object byte[] 32; $rng.GetBytes($bytesAccess)
$bytesRefresh = New-Object byte[] 32; $rng.GetBytes($bytesRefresh)
$bytesField = New-Object byte[] 32; $rng.GetBytes($bytesField)
$bytesQr = New-Object byte[] 32; $rng.GetBytes($bytesQr)

$JWT_ACCESS_SECRET = [System.BitConverter]::ToString($bytesAccess).Replace("-", "").ToLower()

Section 07 // Quality Gate

Automated Environment Health Probe

Run this diagnostic probe to verify that all native Windows services, port bindings, and schema configurations are operational[cite: 10, 15].

Probe Script: test-env.ps1
Write-Host "`n=== BUSVERSE WINDOWS 10 ENVIRONMENT PROBE ===" -ForegroundColor Cyan

# Check 1: PostgreSQL Port
$pg = Test-NetConnection -ComputerName 127.0.0.1 -Port 5432
if ($pg.TcpTestSucceeded) {
  Write-Host "[PASS] PostgreSQL 16 is listening on port 5432" -ForegroundColor Green
} else {
  Write-Host "[FAIL] PostgreSQL 16 is NOT running on port 5432" -ForegroundColor Red
}

# Check 2: Redis Port
$redis = Test-NetConnection -ComputerName 127.0.0.1 -Port 6379
if ($redis.TcpTestSucceeded) {
  Write-Host "[PASS] Redis engine is listening on port 6379" -ForegroundColor Green
} else {
  Write-Host "[FAIL] Redis engine is NOT running on port 6379" -ForegroundColor Red
}

# Check 3: PostGIS Extension Verification
$PG_BIN = "C:\Program Files\PostgreSQL\16\bin"
$postgisCheck = & "$PG_BIN\psql.exe" -U busverse -d busverse_real -h localhost -t -c "SELECT count(*) FROM pg_extension WHERE extname='postgis';"
if ($postgisCheck.Trim() -eq "1") {
  Write-Host "[PASS] PostGIS spatial extension is enabled" -ForegroundColor Green
} else {
  Write-Host "[FAIL] PostGIS extension missing from busverse_real" -ForegroundColor Red
}

# Check 4: .env Distribution Check
$requiredEnvs = @(
  "services\api\.env",
  "services\ws\.env",
  "services\worker\.env",
  "services\simulator\.env",
  "apps\passenger-web\.env.local",
  "apps\operator-panel\.env.local",
  "apps\admin-panel\.env.local",
  "apps\support-panel\.env.local",
  "apps\driver-app\.env"
)
foreach ($file in $requiredEnvs) {
  if (Test-Path $file) {
    Write-Host "[PASS] Found configuration: $file" -ForegroundColor Green
  } else {
    Write-Host "[FAIL] Missing configuration: $file" -ForegroundColor Red
  }
}
Write-Host "=============================================`n"

Windows 10 Troubleshooting Matrix

Direct resolutions for native Windows runtime edge cases[cite: 15].
